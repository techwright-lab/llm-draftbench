# Offline scoring contract v1

`draftbench score` computes deterministic checks and reference-conditioned reviewer
metrics from a self-contained, artifact-bound JSON bundle. It **does not extract
claims with a model, establish world truth, fetch citations, certify human gold,
or rank models**. No generation or provider call is made.

```sh
uv run --offline draftbench score examples/scoring/scoring.json
uv run --offline draftbench score /path/to/private-scoring.json --output /path/to/new-report.json
```

The command is read-only unless a new aggregate report is explicitly requested.
Existing files, including the input, are never overwritten. Exit 0 means the
scoring operation completed, **not** that content passed. A valid report may have
failed checks or only unassessed/undefined metrics. Invalid input or failed
scoring returns exit 2 with safe codes; no private values or tracebacks.

## Inputs and identities

`scoring.schema.json` is generated by `schemas/export.py` from
`draftbench.scoring.models.ScoringBundle`. JSON Schema covers structure; the
Python validator additionally enforces identities, bindings and references.

The self-contained UTF-8 file is bounded to 8 MiB and 4,096 cases. Unknown fields,
coercions, duplicate JSON keys, non-finite numbers, excessive nesting, symlinks and
special files are rejected. No file references or URLs are dereferenced.

A bundle contains its format (`draftbench-scoring-v1`), schema version, identity,
purpose (`synthetic_infrastructure` or `evaluation`), rights and cases. Case and
bundle identities use the existing v1 canonical JSON identity profile. Each case
contains:

- A stable case ID and source family.
- An ordered artifact: units with ID, kind and exact content, plus SHA-256 of
  canonical `{"units": [...]}`. Empty artifacts are structurally representable so
  failed/empty outputs remain in the denominator.
- Rubric ID/version and instance-specific typed checks.
- The supplied source-packet state (`complete`, `partial`, `unavailable`) and
  source IDs, text and SHA-256 of exact UTF-8 text.
- Reference acceptability (`acceptable`, `unacceptable`, `unknown`) and a defect
  inventory (`complete`, `partial`, `unavailable`). Complete empty means known
  absence within this reference; unavailable empty does not.
- An optional parsed reviewer assessment: producer, pass/edit/block/abstain/error
  decision, rubric-item states and defect/suggestion findings.
- Optional attributed alignment judgments for those findings.

References, reviewer assessments and alignments each bind to the exact artifact
hash and rubric ID/version. Changes require rebinding and resealing, not reuse of
stale judgments. Reference and alignment producers, capture basis and declared
independence are explicit. Captured history, reconstruction and synthetic data
are separate bases; none alone proves correctness.

Spans name a unit/source ID, zero-based Unicode-codepoint start/end (end exclusive)
and exact quote. No Unicode normalization or whitespace rewriting occurs. A span
that does not resolve exactly is an invalid measurement, not evidence that the
candidate's content is false.

Duplicate case IDs and duplicate observation targets are rejected. A target binds
artifact, instance-specific rubric, source packet and reviewer configuration;
changing labels, case ID or family cannot mint another observation. Repeated
reviewer trials require a future explicit trial protocol, not duplicated rows.
Conflicting labels belong in adjudication, not duplicate sample counts.

Scoring entrypoints revalidate nested data rather than relying on Pydantic's
shallow `frozen` setting. Hashes authenticate consistency only, not the exporter,
annotation author, actual independence or redistribution rights.

## Deterministic checks

Every check has an ID and declared applicability: required, optional or
inapplicable. Supported checks are:

| Kind | What it establishes |
|---|---|
| `nonempty` | Whether supplied units contain non-whitespace text. |
| `length` | Explicit minimum/maximum Unicode-codepoint counts, per unit or summed across units. Not word counts or platform-specific weighted limits. |
| `required_literal` / `forbidden_literal` | Exact case-sensitive literal presence/absence within units. No regex or semantic paraphrase matching. |
| `citation` | Exact annotated citation span, source membership in the supplied packet, and supplied relevance judgment. It never infers relevance from a URL or term overlap. |
| `fact` | Exact comparison of supplied, span-anchored observed and reference literals/units, conditioned on the declared source relevance. It is not an NLP claim extractor or entailment judge. |

For `fact`, observed value/unit must occur in the candidate quote and reference
value/unit in the supplied source quote. Incorrect annotation anchoring is invalid;
missing reference values or unknown relevance are unknown. Different anchored
dates, numeric strings or units fail the declared comparison. Numerically
equivalent spellings are not silently normalized or converted. This catches the
specified discrepancy, not every other claim in surrounding prose.

A missing cited source in a declared complete packet fails supplied-source
coverage; a missing source in a partial/unavailable packet remains unknown. A
supplied irrelevant-source judgment can fail a check; the scorer does not invent
that judgment. Source support is not proof that the source itself is true.

Explicitly authorized hypothetical/fictional assertions are inapplicable to factual
comparison; they do not create false factual defects. Unapproved nonfactual
assertions cannot bypass the contract. Merely including the word “hypothetical” in
candidate text changes nothing: applicability is attributed input, not an
instruction parsed from the candidate.

Empty output is invalid. Missing/invalid required assessments cannot produce a
pass; no required applicable checks is unassessed, not a vacuous pass. Optional
style-check failures remain visible without vetoing required-check success.
Embedded grader instructions are inert text. Prose polish earns no factual credit.

## Reviewer decisions and denominators

Raw decisions remain visible separately from effective measurement states. Missing
reviews, malformed/internal contradictions and incomplete required coverage are
measurement errors, never implicit passes. Abstention remains distinct from edit,
block and error. A declared pass that also reports a required failure or material
defect is an invalid pass and remains explicitly counted. Here material means
major or critical; a minor finding or optional suggestion alone does not
invalidate a pass. Suggestions are not reference defects.

| Metric | Numerator | Denominator |
|---|---|---|
| False-pass rate | Effective pass on reference-unacceptable items | All eligible known reference-unacceptable items, including abstentions/errors |
| False-block rate | Effective edit or block on reference-acceptable items | All eligible known reference-acceptable items |
| Accepted-set risk | Effective passes labeled unacceptable | Effective passes with known reference labels only |
| Decision coverage | Effective pass/edit/block | All items |
| Abstention rate | Effective abstain | All items |
| Measurement-error rate | Effective measurement error | All items |

Passed items with unknown reference labels are reported separately, never treated
as acceptable and never silently added to the accepted-set-risk denominator.
Always abstaining or always rejecting is not “excellent”: coverage, abstention,
errors and false blocks remain visible alongside false passes. Counts named
`gold_*` in the low-level decision API mean the submitted reference classes;
provenance scope controls their interpretation, not an implicit human-gold claim.

Every rate carries state, numerator, denominator and value. Zero denominators are
undefined/null, never perfect. Insufficient assessment yields unassessed/null.
There is no composite score, confidence interval, calibrated threshold, production
promotion or rare-event safety claim.

## Finding alignment

Predicted defects and optional suggestions are separate. Suggestions are counted
but cannot earn defect true-positive credit. Reference defects and predictions
may include exact spans or an explicitly global/omission finding.

Only supplied attributed judgments create matches or spurious-finding labels.
Unmatched text, similar wording, matching category names and quote overlap do not
establish semantic correctness. Missing judgments remain unassessed. Explicit
ambiguous judgments remain pending adjudication. Two predictions claiming the
same reference defect are treated as ambiguous rather than both earning credit.

Precision uses all predicted defects, not just the favorably adjudicated subset.
Recall uses all declared reference defects; critical recall uses critical
reference defects. Values are withheld when unresolved alignments, invalid spans
or incomplete inventories prevent a defensible denominator. A reference defect
not yet matched is retained for follow-up; it is not asserted missed while an
unresolved prediction could match it. Known critical misses require complete
assessed coverage. Zero predictions or zero defects remains an undefined rate
where the corresponding denominator is zero.

Finding results separately report review coverage: complete for a usable decisive
assessment with full required coverage, unavailable for a missing/error review,
and incomplete for abstention or other nonconclusive review. Recall and known
critical misses require complete review coverage. Returned, explicitly adjudicated
findings from a partial non-error review can still support conditional precision,
but not exhaustive recall; explicit error reviews withhold all point metrics.
Unmatched IDs and attributed counts remain available for follow-up. Annotation
structural validity and review coverage are separate fields: absent coverage is
not falsely described as a malformed quote, nor as a known detection miss.

## Provenance, cohorts and reporting

The scorer retains these distinct conditions:

- `human_reference`: supplied human labels with declared independence; not proof
  that a human really authored them or that annotation quality was validated.
- `synthetic_reference`: explicitly fabricated infrastructure-test labels.
- `auxiliary_model_agreement`: agreement with model-produced reference judgments.
- `workflow_agreement`: agreement with workflow-generated labels.
- `self_agreement`: declared same-system references, not independent correctness.
- `unassessed`: reference producer/independence needed for interpretation is absent.

Finding metrics also retain alignment provenance. Human reference defects plus
model-produced matching decisions are not silently reported as human-validated
finding correctness. Unresolved/incompatible conditions withhold the value.

Decision cohorts separate rubric ID/version, exact reviewer producer configuration,
reference producer/basis and reference scope. Check parameters may be
instance-specific within one versioned rubric. Different reference conditions are
never pooled into one unqualified gold average. The aggregate CLI omits IDs,
producer names, hashes, paths, quotes and label text; anonymous cohort indexes
refer to separate groups, not rank positions. Detailed pending IDs are available
only through the in-memory library result for later private annotation handling.

All related cases retain source-family grouping. Artifact/rating counts are not
independent safety samples. A future report/annotation layer must provide approved
identity mappings and independent adjudication rather than inferring them from
these anonymous aggregates.

## Deliberately deferred

No general natural-language factuality/style judge, claim extractor, live citation
retrieval, TG rubric replacement, automatic conversion of TG workflow labels to
human gold, annotation export/import, revision-gain score, outcome experiment,
public leaderboard or provider execution is included. TG's private export remains
source material; it must be transformed into this explicit artifact-bound scoring
contract without fabricating missing evidence or independent judgments.
